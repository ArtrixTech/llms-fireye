# 方法论

## 要回答的问题

一个中转站说它卖的是模型 L。fireye 只回答一件事：**它给你的回答里，有没有不是 L 给的，大概多少。**

"不是 L"包括三种情况，都算掺水：

- 整体冒充：全部请求都转给了别的模型（另一家，或同家族的便宜型号，比如 sonnet 冒充 opus、flash 冒充 pro）
- 部分掺水：一部分请求转给便宜模型
- 库外冒充：转给了指纹库里没有的模型

## 主线

1. **出题**：每条请求是一道无语义的选数字题——"随手写 292–332 个 1 到 355 的整数"。题面随机组合，每条独立。
2. **指纹**：模型写数字有稳定的偏好（喜欢哪些数、怎么排）。一条回答里几百个数字的分布，就是这条回答的行为指纹。这个方法来自 [ModelTrace](https://github.com/xqy2006/ModelTrace)，fireye 用的是 [ArtrixTech/ModelTrace](https://github.com/ArtrixTech/ModelTrace) fork 的 `fireye` 分支。
3. **逐条比对**：每条回答单独和指纹库比对，得到"这条回答来自库里每个模型的概率"。每条回答归入三类之一：
   - ✓ 像 L：最像的就是 L；
   - ≈ 更像别的模型：最像的不是 L，但 L 的概率仍在阈值 τ 以上，单条不能排除 L；
   - ✗ 明显不像 L：L 的概率低于 τ。
4. **判定**：真模型偶尔也会有回答落到 ≈ 或 ✗，两种比例都是对每个标签实测的。数两个数：明显不像的条数 k，和更像别的模型的条数 j（含 k）。任一超出真模型能解释的范围（真模型出现这么多条的概率各 ≤1%，合计 ≤2%），就判为可疑。k 抓"少数几条差得很远"，j 抓"很多条都略偏"。
5. **能排除多少**：没发现可疑时，报告"若掺水比例 ≥X%，有 95% 把握能发现"。X 由样本量、ε 和每条被掺回答被抓到的概率 d 算出。

所有请求同时并行发出（受 `--concurrency` 限制），快速模式 9 条，深度模式 30 条。

## 结论

| 结论 | 条件 |
|---|---|
| ✅ 未发现掺水 | k、j 都在真模型的正常波动内，且所有回答合起来也最像 L（报告和界面仍会列出 ≈ 的条数和可疑线） |
| 🟠 发现可疑回答 | k 或 j 超出正常波动，但不到一半的回答更像别的模型；或单条都不能排除 L、合起来却更像别的模型 |
| ❌ 不是声称的模型 | 已判可疑，且超过一半的回答更像别的模型 |
| ⚪ 无法判定 | 有效回答不到 3 条（空响应、报错、拒答、数字太少） |
| ⚪ 无法核实 | 指纹库里没有 L，只能报告它像谁 |

## 指纹库

当前 23 个模型（`vendor/modeltrace/data/unified_bank.json`）：

- 闭源 18 个：gpt-5.4 / 5.5 / 5.6-sol / 5.6-terra / 5.6-luna / 6-astra / 6-sol / 6-luna；claude-haiku-4-5 / sonnet-4-6 / opus-4-6 / opus-4-7 / opus-4-8 / opus-5 / sonnet-5 / opus-5-5 / sonnet-5-5 / haiku-5-5
- 开源 5 个：glm-5.3、glm-5.3-flash、kimi-k3、deepseek-v4-pro:0813、deepseek-v4.1-flash
- 采集中（Ollama Cloud 用量额度用完，额度恢复后续采）：minimax-m3 / m2.7、kimi-k2.7-code / k2.6、glm-5.2、mistral-large-4 / 3、gpt-oss:120b / 20b、nemotron-3 ultra / super / nano、gemma4:31b。Qwen 不在 Ollama Cloud 上，暂缺。

闭源模型的参考数据来自 ModelTrace 上游（官方渠道采集）。开源模型由 fireye 通过 Ollama Cloud 采集（`research/collect_ollama.py`），使用与上游完全相同的 36 道题和 12 种提示词包装（无包装 / system 提示词 / user 前缀），可以直接比较。

## 准确度（有标准答案的模拟）

真模型被误报（判成可疑或冒充）：按设计 ≤2%。每个标签模型单独控制，快速 9 条时平均 1.1%，深度 30 条时 0.8%。

掺水被发现（判成可疑或冒充）的概率，r 为掺水比例：

| 掺入的是 | 样本 | r=10% | r=25% | r=50% | r=100% |
|---|---|---|---|---|---|
| 库内任意模型 | 快速 9 | 54% | 86% | 99% | 100% |
| 库内任意模型 | 深度 30 | 71% | 99% | 100% | 100% |
| 库外模型（没见过） | 快速 9 | 44% | 74% | 93% | 99% |
| 库外模型（没见过） | 深度 30 | 59% | 93% | 99% | 99.7% |
| 开源冒充闭源，库内 | 快速 9 | 55% | 88% | 99% | 100% |
| 开源冒充闭源，库外 | 快速 9 | 46% | 79% | 96% | 100% |
| 开源冒充闭源，库外 | 深度 30 | 64% | 96% | 100% | 100% |

最难的情况是库外的同家族型号，比如一个没进库的 Claude 型号冒充 claude-opus-4-8：快速模式下整体替换也可能有 80% 以上的概率判为"未发现掺水"。开源冒充闭源跨家族，差异大，即使模型不在库里也基本能发现。

阈值怎么定：每条回答"像 L 的概率"低于 τ 记为"明显不像 L"。τ 随样本量变化（样本少时用很严的 τ，单条判偏就有意义；样本多时放宽 τ、要求 2–6 条判偏）。每个标签模型的 k\* 和 j\*（最少几条才算可疑）按它自己的实测比例单独定（向全体平均收缩，避免样本少的模型被高估或低估），各保证真模型误报 ≤1%。真模型"更像别的模型"的比例差别很大：claude-opus-5-5 在参考数据里 0/36，claude-opus-4-8、kimi-k3、glm-5.3-flash 在 8–10/36，所以同样 30 条，j\* 从 5 到 13 不等。在这个约束下，τ 取使"掺水 25% 和 50% 时的发现率（库内与库外平均）"最高的值，发现率按 k、j 的联合（三项分布）计算。结果存在 `lib/calibration.json`。

测法：12 种提示词包装分成 3 组，每次用其中 2 组重建指纹库，剩下 1 组的回答当作中转站的回答，这样被测回答所在的包装方式指纹库从没见过。模拟一个声称是 L 的中转站，每次请求以概率 r 改由 S 回答，走 fireye 的真实判定流程，统计结论。"库外"场景会把 S 从指纹库里删掉，模拟遇到没见过的模型。脚本：`scripts/calibrate.mjs`（数据由 ModelTrace `research/fn_banks.py` 生成）。

## 局限

- **样本量决定下限**：掺水比例很低时，9 条回答里可能一条都没抽到掺水的回答，任何方法都测不出。需要排除低比例掺水时用深度模式，并换时段复测（有的站按时段、流式/非流式分流）。
- **库外模型**：库外模型冒充时，会被判成库里最像的模型。和声称模型同家族时最容易漏判（见上表"库外"行）。持续扩充指纹库是主要对策。
- **识别测试题**：站点如果能认出测试题、专门转给真模型，任何指纹测试都测不出来。
- **参考数据都来自官方或 Ollama 渠道**：中转站套的外壳（长系统提示词等）会让指纹略微偏移。指纹库的 12 种包装覆盖了常见情况。用新规则重判历史报告（`scripts/replay-reports.mjs`）：原判 PASS 的 22 条车道里 21 条仍为未发现掺水，1 条（一个 haiku 车道）因为有一条回答最像 gpt-5.5、像 haiku 的概率不到百万分之一，改判可疑；但这些渠道没有标准答案，不能当作误报率的证明。
- **标定数据有限**：每个模型 36 条参考回答。真模型判偏率 ε 用这些回答估计（并向全体平均收缩），误报率 ≤2% 是在同一批数据上算的，换到没见过的外壳上可能略高。开源模型参考数据来自 Ollama Cloud，若中转站用的是其他服务商的部署（量化方式不同），指纹可能略有偏移。
- **自报身份不作证据**：模型自称什么由站点注入的提示词决定。

注入大小、外壳指认、面板侦查等人工溯源步骤见 [FORENSICS.md](FORENSICS.md)。
